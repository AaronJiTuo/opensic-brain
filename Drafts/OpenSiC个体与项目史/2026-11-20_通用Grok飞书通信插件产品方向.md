# 通用 Grok Bot 飞书通信插件（产品方向）

**性质**：Aaron 于 2026-11-20 明确的产品方向记录。**未开发、未端到端验证、未上线。** 不要与韩思婵任期内的内部飞书桥接 PoC 混淆；PoC 也不是已验收成果。

## 要解决什么

让用户能够**自行**在飞书开发者后台创建应用机器人，再在 Grok Bot 侧安装并配置同一套插件；两边填写约定配置项（密钥、URL 等）后，将**一个或多个**既有 Grok Bot 各自配对到对应的飞书应用，获得接近 Slack 频道体验的单聊与群聊（含 @），且各用户、各 Bot 的凭据与会话**相互隔离**。

## 明确不是

- **不是**一键替用户创建飞书应用（飞书 OpenAPI 不能代建机器人身份）。
- **不是** Grok Bot 原生 Slack 频道的完全等价物。
- **不是**把 webhook 当作完整聊天接口：Grok Bot webhook 偏任务触发，多轮上下文、会话隔离与回传须由配套能力处理并验证。
- **不是**提交即可上架：若走应用市场须官方审核。

## 目标形态（待验证）

| 要素 | 方向 |
| --- | --- |
| 用户侧 | 自建飞书应用、发布与授权 |
| Bot 侧 | 安装通用插件，按说明填 key / URL |
| 中继 | 由插件配套提供，避免每位用户自写桥接代码 |
| 技术候选 | MCP 出站 + webhook 入站 + 中继（**路线未经证实**） |
| 多实例 | 同一插件可重复用于不同用户、不同 Bot |

## 建议的验证顺序

1. **单 Bot ↔ 单飞书应用** 完整配对与连续对话链路。
2. 确认用户侧**不必写代码**、也不必自行排查桥接问题。
3. 验证通过后再产品化、考虑上架。

## 与 OpenSiC 项目关系

- 2026-11-03 立项时，韩思婵的首个子项目表述为面向内部同事的**飞书桥接**；技术实施由吴思春负责。
- 2026-11-20 讨论的**通用可配置插件**是更宽的产品方向，**不记作**韩思婵个人已交付成果，也**不记作**已实现能力。
